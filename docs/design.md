# EditVideo 設計書（v0.1）

Windows 向け・Rust 製のシンプルな動画編集 GUI アプリ。個人利用を前提とする
（インストーラ・コード署名・多言語対応・ffmpeg 同梱は行わない）。

## 1. 要件整理

### 必須（MVP）
| ID | 機能 | 内容 |
|----|------|------|
| F1 | 動画を開く | mp4 / mov / mkv / webm などを読み込み、長さ・解像度・fps を表示 |
| F2 | プレビュー | 再生 / 一時停止 / シーク / コマ送り（前後1フレーム） |
| F3 | カット編集 | 再生位置で分割 → 不要セグメントを削除 → 残りを連結して書き出し |
| F4 | 範囲切り出し | IN / OUT 点を指定し、その範囲だけを書き出し |
| F5 | 書き出し | 「正確（再エンコード・フレーム単位）」を既定とし、「高速（無劣化・キーフレーム単位）」も選択可能。進捗表示・キャンセル |
| F6 | Undo / Redo | 編集操作の取り消し・やり直し |

### 後続バージョン
| 版 | 機能 |
|----|------|
| v0.2 | 音声付きプレビュー、プロジェクトファイル保存 |
| v0.3 | 複数ファイルの結合（データモデルは MVP 時点で対応済みにしておく） |

### 対象外
- トラック重ね合わせ、テキスト・エフェクト・トランジション

### 非機能
- 起動が速く、単一 exe で動く（ffmpeg はインストール済みのものを外部実行ファイルとして利用）
- 長尺動画（1時間以上）でも UI が固まらない（デコード・書き出しは別スレッド）

## 2. 技術選定

| 領域 | 採用 | 理由 / 比較 |
|------|------|------------|
| GUI | **eframe / egui** | 純 Rust・ビルドが容易・タイムラインのような自前描画が書きやすい。iced / Slint も候補だが、カスタム描画と即時モードの手軽さで egui を選択 |
| デコード / エンコード | **ffmpeg CLI をサブプロセス実行** | 環境に ffmpeg 9.0.2 あり。`ffmpeg-next` 等のバインディングは Windows でのビルド（dev ライブラリ・LLVM）が重いため避ける |
| メディア情報取得 | `ffprobe -print_format json` | serde_json でパース |
| ファイルダイアログ | rfd | ネイティブダイアログ |
| 音声プレビュー | （v0.2）rodio + ffmpeg の PCM 出力 | MVP は映像のみプレビュー（後述） |

### 追加クレート（承認済み）
- `eframe`（egui 含む）
- `serde`, `serde_json`
- `rfd`
- `anyhow`
- （v0.2）`rodio`

スレッド間通信は `std::sync::mpsc` を使い、追加クレートは入れない。

## 3. 全体アーキテクチャ

```
┌──────────────────────── UI スレッド (eframe) ────────────────────────┐
│  app.rs : AppState / 画面描画 / 入力処理                              │
│    ├─ ui/preview.rs   : プレビュー画像表示（egui Texture）             │
│    ├─ ui/timeline.rs  : タイムライン（セグメント・再生ヘッド・IN/OUT）  │
│    └─ ui/export.rs    : 書き出しダイアログ・進捗バー                   │
│                                                                      │
│  model/  : 純粋ロジック（UI・ffmpeg に依存しない → 単体テスト対象）     │
│    ├─ time.rs      : Timestamp（マイクロ秒 i64）・フレーム換算          │
│    ├─ timeline.rs  : Timeline / Segment / 編集操作                    │
│    └─ history.rs   : Undo/Redo（Timeline のスナップショット方式）       │
└───────────┬──────────────────────────────────────▲───────────────────┘
            │ コマンド (mpsc)                        │ フレーム / 進捗 (mpsc)
┌───────────▼──────────────┐          ┌─────────────┴────────────────┐
│ media/player.rs          │          │ export/runner.rs             │
│  デコードワーカースレッド  │          │  書き出しワーカースレッド      │
│  ffmpeg → rawvideo pipe  │          │  ffmpeg -progress pipe:1     │
└───────────┬──────────────┘          └─────────────┬────────────────┘
            │                                        │
       media/probe.rs (ffprobe)            export/command.rs（引数生成・純粋関数）
       media/ffmpeg.rs (exe 探索・プロセス起動共通)
```

設計方針
- **model は純粋**：ffmpeg や egui に依存させず、テスト容易にする。
- **ffmpeg 引数生成は純粋関数**：`Timeline → Vec<OsString>` をテストで検証し、実行部と分離。
- **UI はブロックしない**：重い処理はすべてワーカースレッド。UI は毎フレーム `try_recv` で結果を受け取る。

## 4. データモデル

```rust
/// マイクロ秒単位の時刻（浮動小数の誤差を避ける）
pub struct Timestamp(i64);

pub struct MediaInfo {
    pub path: PathBuf,
    pub duration: Timestamp,
    pub width: u32,
    pub height: u32,
    pub fps: Rational,           // 例: 30000/1001
    pub has_audio: bool,
    pub video_codec: Option<String>, // 例: "h264"（高速モードの連結可否判定用）
    pub audio_codec: Option<String>, // 音声なしなら None
}

/// 読み込んだ素材の識別子（Timeline::sources の添字）
pub struct SourceId(usize);

/// 素材上の区間 [start, end)
pub struct Segment {
    pub source: SourceId,
    pub start: Timestamp,        // 素材内の時刻
    pub end: Timestamp,
    pub enabled: bool,           // false = 削除扱い（書き出し対象外）
}

pub struct Timeline {
    pub sources: Vec<MediaInfo>,
    pub segments: Vec<Segment>,  // タイムライン上の並び順
    pub in_point: Option<Timestamp>,  // タイムライン上の時刻
    pub out_point: Option<Timestamp>,
}
```

「削除＝`enabled=false`」としてセグメント自体は残すことで、
タイムライン上に削除箇所をグレー表示でき、Undo も単純になる。

### 時刻の2つの座標系
- **素材時刻**：各素材ファイル内の時刻（`Segment.start/end`、ffmpeg に渡す値）
- **タイムライン時刻**：セグメントを並べた先頭からの時刻（再生ヘッド・IN/OUT・UI 表示）

タイムライン時刻はセグメント長の累積和で求める。`Timeline::locate(t) -> (セグメント番号, 素材時刻)` で相互変換する。
削除済みセグメントもタイムライン上には幅を持って表示する（書き出し時に詰める）。

### 複数ファイル対応の準備（v0.3）
- MVP では `sources` は常に1件だが、モデル・書き出しコマンド生成は `SourceId` を通して素材を参照する。
- v0.3 で「ファイルを追加」すると、その素材全体を覆う1セグメントを末尾に追加する。
- 解像度・fps が異なる素材の連結は正確モードのみ対応し、先頭素材に合わせて `scale` + `pad` + `fps` フィルタで揃える。高速モードはコーデック・解像度が一致する場合のみ許可する。

### 編集操作（`Timeline` のメソッド）
| 操作 | 動作 |
|------|------|
| `split_at(t)` | タイムライン時刻 t を含むセグメントを2分割 |
| `locate(t)` | タイムライン時刻 → (セグメント番号, 素材時刻) |
| `toggle(idx)` / `delete(idx)` | セグメントの有効/無効切替 |
| `delete_range(a, b)` | 区間 [a,b) を分割して無効化（IN/OUT 範囲の削除、Q/W のトリミングにも使う） |
| `prev_edit(t)` / `next_edit(t)` | t の直前 / 直後のセグメント境界を返す（↑↓ 移動・Q/W 用） |
| `set_in(t)` / `set_out(t)` | 切り出し範囲の設定 |
| `export_ranges(mode)` | 書き出し対象区間の列を返す。切り出しモードなら [IN,OUT) ∩ 有効セグメント |

### Undo / Redo
編集操作の前に `Timeline` を clone して undo スタックへ積む（スナップショット方式）。
セグメント数は高々数百程度なのでメモリ的に問題なし。コマンドパターンより実装が単純で壊れにくい。

## 5. プレビュー（media/player.rs）

### 方式
ワーカースレッドで以下を起動し、標準出力から RGBA フレームを読む。

```
ffmpeg -hide_banner -loglevel error -nostdin -ss <素材時刻> -i <file>
       -map 0:V:0 -an -sn -dn -vf scale=<W>:<H> -pix_fmt rgba -f rawvideo pipe:1
```
- 出力サイズは素材の解像度からアスペクト比を保って算出し（幅上限 960px・拡大しない・偶数に丸め）、
  `scale=W:H` で明示する。stdout から W×H×4 バイトずつ読む。stderr は別スレッドで読み捨てる（末尾はエラー表示用に保持）。
- **シーク位置**：ffmpeg の入力シークは「pts ≥ -ss の最初のフレーム」を出す（実測）。表示したいフレーム k
  （時刻 t を含むフレーム = `frame_at` の floor）の開始時刻から**半フレーム手前**を `-ss` に渡し、
  素材側の時刻の丸め（mkv の 1ms 単位など）に影響されないようにする。
- 読み出した n 枚目のフレームの素材時刻は `fps.frame_start(k + n)`（rawvideo 出力は既定で CFR）。
  これをセグメントのタイムライン位置に変換して UI へ渡す（UI とのやりとりはすべてタイムライン時刻）。
- ワーカーは `Timeline` のスナップショット（clone）を持つ。UI 側でセグメント構成が変わったら `SetTimeline` で差し替え、現在位置を表示し直す。
- **ハードウェアデコードは使わない**：`-hwaccel d3d11va` を実測（Ryzen 5 5600G、960px・RGBA 出力）したところ、H.264 1080p / 4K・HEVC 4K のいずれもシーク1枚・連続デコードとも 2〜3 倍遅かった（GPU からの転送と縮小の負担が上回る）。

### コマンド / イベント
- UI → worker（mpsc）：`Seek(t)` / `Play` / `Pause` / `StepFrame(±n)` / `SetTimeline` / `SetPreviewWidth` / `Shutdown`
- worker → UI：`Frame { time, width, height, rgba }` / `State(Playing|Paused)` / `Ended` / `Error`。送信のたびに notify（`request_repaint`）を呼ぶ。
- 処理前にキューを `try_recv` で吸い出し、連続する `Seek` は最後の1件に、連続する `StepFrame` は合算する。

### 状態遷移
```
Idle ──open──▶ Paused ──play──▶ Playing
                 ▲  │              │
                 └──┴──pause/seek──┘
```
- **一時停止中のシーク**：ffmpeg を起動 → 1フレーム読んで表示。プロセスは保持し、次の操作が
  同じセグメントの少し先（15フレーム以内）なら読み進めて使い回す（コマ送り・その後の再生が速い）。それ以外は kill → 再起動。
- **再生**：再生開始時刻と壁時計から目標時刻を求め、次フレームの時刻まで `recv_timeout` で待つ（待ち中もコマンドを受け付ける）。
  1フレーム以上遅れたフレームは読み捨てる（連続 5 枚まで）。プロセスを起動し直した場合は最初のフレームを読んだ時点からクロックを進める。
  UI が未受信のフレームが 2 枚以上あれば送らない（最小化中などのメモリ増加防止）。停止時は最後に読んだフレームを必ず届ける。
- **セグメント境界**：同じ素材で素材時刻が連続する次セグメントならプロセスを使い続け、それ以外は次セグメントの素材・素材時刻で再起動する。
- **再生中に無効セグメントへ入ったら**次の有効セグメント先頭へ自動ジャンプ（カット結果の確認用）。再生開始位置が無効セグメント内の場合も同様。
  一時停止中のシークでは無効セグメント内も表示する。
- **末尾**：`Ended` → `State(Paused)`。末尾で再生すると先頭（最初の有効セグメント）から再生する。
- 素材の映像が表記の長さより短く、指定位置にフレームが無い場合は 1 秒手前から読み直して最後のフレームを表示する。
- **コマ送り**：現在フレームの番号 ± n のフレーム開始時刻へシーク（タイムライン範囲にクランプ）。再生中なら一時停止してから。
- プロセスは `Decoder` の Drop で kill → wait する。`Player` の Drop で `Shutdown` を送りスレッドの終了を待つ。

### 画面（今回の範囲）
- `ui/preview.rs`：`TextureHandle` を `set` で更新し、利用可能領域にアスペクト比を保って中央表示。
- プレビュー下に簡易トランスポート（先頭 / 1フレーム戻る / 再生・一時停止 / 1フレーム進む / 末尾、現在時刻 / 総尺、シークスライダー）と
  「現在位置を IN / OUT に」。キーは Space・← / → のみ（テキスト入力中は無効）。本格的なキーマップは 12章5 で実装する。

### 音声について
MVP は映像のみ。音声付きプレビューは A/V 同期が必要で複雑になるため v0.2 で
rodio + `ffmpeg -f s16le pipe:1` により実装し、音声クロックをマスターにする。

## 6. 書き出し（export/）

### モード
| モード | 方式 | 速度 | 精度 |
|--------|------|------|------|
| **正確（再エンコード）※既定** | 区間ごとに入力シーク付きで入力し、`concat` フィルタで1パス連結 | 遅い | フレーム単位 |
| 高速（無劣化） | 区間ごとに `-ss a -to b -c copy` で一時ファイル化 → concat demuxer で連結 | 非常に速い | キーフレーム単位（開始位置がずれる） |

高速モードでは、区間開始がキーフレームでない場合 UI で警告を出し、
「最寄りのキーフレームにスナップ」ボタンを用意する。
- キーフレーム位置は書き出し設定で高速モードを選んだときに別スレッドで取得する
  （`ffprobe -select_streams V:0 -show_entries format=start_time:packet=pts_time,flags -of csv`。
  パケットのみ読みデコードしない。`start_time` を引いて素材時刻にする）。Undo のスナップショットに含めないようアプリ側で素材ごとに保持する。
- 判定は書き出し区間ごと。開始とフレーム番号が同じキーフレームがあれば OK（`Timeline::keyframe_issues`）。
- スナップ（`Timeline::snap_to_keyframes`、Undo 可）：区間内または直前の削除済み部分（同じ素材で連続）にある最寄りのキーフレームへ寄せる。
  開始が IN 点なら IN を動かす。後ろへ寄せる場合はその間を削除、前へ寄せる場合は削除済み部分を復元する。IN が削除部分の中にあるときは IN より前には寄せない。

### 正確モードのコマンド例（2区間）
```
ffmpeg -hide_banner
       -ss 0.000000 -to 5.000000  -i in.mp4
       -ss 10.000000 -to 20.000000 -i in.mp4
 -filter_complex "[0:V][0:a][1:V][1:a]concat=n=2:v=1:a=1[v][a]"
 -map [v] -map [a] -c:v libx264 -preset medium -crf 20 -pix_fmt yuv420p -c:a aac
 -movflags +faststart -progress pipe:1 -nostats -y out.mp4
```
- 区間ごとに別入力とし、`-i` の前に `-ss/-to` を置く（入力シーク）。再エンコード時の入力シークはフレーム単位で正確で、
  `trim` フィルタと違って先頭から全デコードしないため長尺動画でも速い。区間が1つでも同じ方式。
- 時刻は `Timestamp` からマイクロ秒精度の秒文字列（例 `12.345678`）にする（浮動小数を経由しない）。
- 映像は `[i:V]`（添付画像を除く映像）を使う。
- 入力が素材ごとではなく区間ごとなので、複数ファイル連結（v0.3）も同じ形で扱える。
- **フィルタのファイル渡し**：フィルタ文字列が 4000 文字を超える、またはコマンドライン全体の見積もり長が
  31743 文字（Windows の 32767 文字 − 実行ファイルパス用の余裕 1024）を超える場合は、
  一時ディレクトリの `filter.txt` に書き出し `-/filter_complex <path>` で渡す（ffmpeg 7 以降で `-filter_complex_script` は非推奨）。
  それでも入力指定（`-ss/-to/-i` × 区間数）だけで上限を超える場合はエラーにする。
- **音声**：
  - 全素材が音声なし → `a=0`、`-map [v]` のみ、`-c:a` も付けない。
  - 1つでも音声あり → `a=1`。音声なし素材の区間は、フィルタ内で `anullsrc=r=48000:cl=stereo:d=<区間長>` の無音を生成して埋める
    （入力を増やさない）。サンプルレート・チャンネル数の違いは concat の形式ネゴシエーションで自動変換される。
- **解像度・fps の統一**：先頭区間の素材の解像度（yuv420p のため偶数に切り下げ）・fps を基準とし、
  いずれかの区間の素材が異なる場合のみ全映像に
  `scale=W:H:force_original_aspect_ratio=decrease,pad=W:H:(ow-iw)/2:(oh-ih)/2,setsar=1,fps=F` を入れる。
- エンコーダ設定（MVP）：H.264 + AAC、品質プリセット（高/標準/軽量 → CRF 18/20/23、既定は標準）。

### 高速モードの手順
1. 区間ごとに `-ss a -to b -i src -map 0:V -map 0:a? -c copy -avoid_negative_ts make_zero <tmp>/part_NNNN.<出力の拡張子>`
   （添付画像・字幕・データストリームは連結時に失敗しやすいため映像と音声のみ）。
2. `<tmp>/list.txt` に `ffconcat version 1.0` と `file 'part_NNNN.ext'`（リストからの相対パス。`'` は `'\''` にエスケープ）を書く。
3. `-f concat -safe 0 -i list.txt -map 0 -c copy -movflags +faststart -progress pipe:1 -nostats -y out` で連結。
- 素材が複数ある場合、コーデック（映像・音声）・解像度・fps・音声有無がすべて一致しなければエラー（`MediaInfo` に `video_codec` / `audio_codec` を持たせる）。

### 進捗・キャンセル
- `-progress pipe:1` の `out_time_us`（または `out_time_ms`。値はどちらもマイクロ秒）を読み、書き出し総尺に対する割合を算出。
- 高速モードは「区間ごとのコピー（各区間長）＋連結（総尺）」を重みとして段階的に進捗を出す。
- stderr は別スレッドで読み続け（パイプ詰まり防止）、末尾 30 行を保持する。
- 一時ファイルは `std::env::temp_dir()` 配下に一意名のディレクトリを作って置き、成功・失敗・キャンセルいずれでも削除する。
- キャンセル時はプロセス kill → 出力途中ファイルと一時ファイルを削除。
- 失敗時は stderr の末尾を含めたメッセージをエラーダイアログに表示し、出力途中ファイルを削除。
- 出力先が入力素材と同じファイルの場合は開始前にエラー（上書き防止）。

### キーボードショートカット（Adobe Premiere Pro の Windows 既定に準拠）

#### 再生・移動
| キー | 動作 | Premiere での名称 |
|------|------|------------------|
| Space | 再生 / 停止 | 再生/停止 |

マウス操作：タイムラインのドラッグで再生ヘッド移動（スクラブ）、Alt+ホイールでズーム（Premiere 準拠）。

※1 **逆再生**：ffmpeg のパイプ出力は順方向のみのため、逆再生は「少し前へシーク → 数フレームまとめてデコード → 逆順に表示」を繰り返して実現する。順再生より表示が粗くなる場合がある。
**現状**：プレイヤーが倍速・逆再生に未対応のため、L = 等速再生、K = 停止、J は無効（K 押しながら L / J のコマ送りは対応済み）。シャトルはプレイヤー改修と合わせて後続で実装する。

※2 **Premiere との違い**：Premiere の「消去」「リフト」は隙間を残すが、本アプリはトラックが1本で隙間の概念がない。削除した箇所は書き出し時に必ず詰めて連結するため、「消去」と「リップル削除」、「リフト」と「抽出」は同じ動作になる。

#### 実装方針
- キー割り当ては `ui/keymap.rs` に「キー＋修飾キー → `Action` 列挙型」の表として一か所にまとめる。UI 側は `Action` だけを扱い、将来の割り当て変更（設定ファイル化）に備える。
- `;` と `'` は配列による文字の位置ではなく、入力された文字で判定する（日本語キーボードでは `'` は Shift+7）。
- テキスト入力欄にフォーカスがある間はショートカットを無効にする。

## 8. ffmpeg の扱い

インストール済みの ffmpeg / ffprobe を使う（同梱しない）。探索順：
1. 設定ファイル（`%APPDATA%\EditVideo\config.json`）で指定されたパス
2. PATH

見つからなければ起動時にダイアログで案内し、パスを指定できるようにする（ffmpeg.exe を選ぶと同じフォルダの ffprobe.exe と合わせて設定ファイルに保存し、探し直す。PATH 追加後の「再検索」も可）。サブプロセスは
`CREATE_NO_WINDOW` フラグで起動し、コンソール窓を出さない。

## 9. エラー処理
- ライブラリ層は `anyhow::Result`。UI 層でユーザー向け文言に変換して通知。
- ffprobe 失敗（非対応形式）、ffmpeg 未検出、書き出し失敗、出力先の上書き確認を扱う。
